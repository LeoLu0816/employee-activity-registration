## 專案目標

- 學員有舊版 ASP.NET MVC 經驗，並熟悉 Vue 3、TypeScript、Node.js 與 AWS；課程補齊現代 .NET 的基礎與實作差異。
- 業務保持小，學習深度放在實作、驗證、除錯與服務使用經驗。
- 後端核心由學員練習；前端可由 AI 依 API 契約完成。
- GitHub 保留程式碼、測試、效能實驗與文件，網站提供面試官可操作的展示流程。
- Azure 以低流量、長期展示為目標；月費上限尚未定案，部署前先估價。

## 最小產品範圍

活動包含外部講師課程、運動、手作與技術分享。活動類型只是分類，全部共用相同的報名邏輯。

第一版提供四個流程：

1. 查看活動列表與詳情。
2. 報名活動。
3. 取消自己的報名。
4. 查看自己的報名紀錄。

核心規則：

- 同一員工、同一活動只能有一筆有效報名。
- 有效報名數不得超過活動名額。
- 員工只能取消自己的報名；重送取消不會重複釋放名額。
- 取消後可重新報名，仍須符合名額限制。

活動與展示員工先以種子資料建立。正式展示使用身分驗證；前期尚未完成登入時，只能在本機以伺服器設定的固定員工練習，不接受用戶端自行指定身分。

付款、候補、簽到、通知、部門配額、主管審核、企業 SSO、多公司與管理後台，均不列入本課程必做項目。若未來新增，另行討論範圍。

## 技術與結構方向

- .NET 10 LTS、ASP.NET Core Controllers、EF Core 10、SQL Server。
- ASP.NET Core Identity 管理預建帳號；Cookie 登入，同源部署，避免自行設計密碼儲存與 Token 系統。
- Redis 用於可容忍短暫過期的讀取資料；資料庫保證名額與報名正確性。
- xUnit、WebApplicationFactory、真實 SQL Server 整合測試；Redis 單元使用真實 Redis。
- Docker Compose 建立本機依賴；k6 執行可重現的壓力測試。
- Vue 3 + TypeScript 由 AI 製作；先完成 API，再接畫面。
- 一個後端應用，按活動、報名與身分分組；從簡單結構開始，按實際需要拆分。

未來程式碼預計放在 `src/`、測試放在 `tests/`、壓測放在 `load-tests/`、部署設定放在 `infra/`。目前只有 `docs/` 文件，這些程式目錄尚未建立。

## API 方向

採 GET 查詢、POST 執行動作；變更操作的識別值放在 body。員工身分從伺服器的登入資訊取得。

| 方法與路徑 | 用途 |
|---|---|
| `GET /api/activities` | 活動列表，逐步加入分類與分頁 |
| `GET /api/activities/detail?activityId=...` | 活動詳情 |
| `GET /api/registrations/mine` | 自己的報名紀錄 |
| `POST /api/registrations/create` | body 提供 `activityId`，建立或恢復報名 |
| `POST /api/registrations/cancel` | body 提供 `registrationId`，取消自己的報名 |
| `POST /api/auth/login` | 使用預建展示帳號登入 |
| `POST /api/auth/logout` | 登出 |

回應狀態、DTO 與錯誤代碼在對應課堂確定，並以 OpenAPI 與測試維護。

- 四個核心流程可在 Azure 網站操作，兩個展示員工可切換體驗。
- 登入、資料所有權、重複請求、取消與重新報名皆有驗證。
- 100 個不同員工競爭 20 個名額，最終恰好 20 筆有效報名，且無重複或負數計數。
- 留下索引與 Redis 的改善前後實驗；結果必須附資料量、環境與測試方法。
- 有本機啟動、測試、部署、資料重建與復原方式。
- 記錄 Azure 實際用量、費用與冷啟動體驗，不把本機壓測當成雲端容量保證。
- 能用三分鐘說清楚需求、設計、驗證與取捨；效能數字以實測為準。
