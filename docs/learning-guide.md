# 學習方式與 AI 協作

## 分工

這個專案的主要產出包含學員的理解與實作能力。AI 擔任教練與審查者，前端則可以由 AI 完整製作。

| 工作 | 方式 |
|---|---|
| 後端核心、SQL、交易與快取 | 學員先練習，AI 給提示、說明與審查 |
| 重複樣板、測試資料與環境設定 | 先說明用途，再依當堂需求協助產出 |
| Vue 3 + TypeScript 畫面 | AI 依 API 契約製作，學員檢查互動 |
| 測試與效能報告 | 實際執行後記錄，學員能重跑並解釋 |
| Azure 登入與費用選擇 | 學員自行登入；建立付費資源前先呈現具體估價與配置 |

## 每堂課的流程

1. 從 `progress.md` 的 `next_step` 接續，只確認與本堂相關的環境。
2. 說明本堂要解決的具體問題與完成條件。
3. 補充必要概念，第一次出現的術語用白話解釋。
4. 一次給一個約 15～30 分鐘的練習，讓學員先預測結果並動手。
5. 卡住時依序提供提示、局部範例、必要的最小解答。
6. 執行針對性驗證，檢查資料與實際行為，不只看程式碼。
7. 由學員回答一至三題，確認能解釋用途、失敗情境與取捨。
8. 記錄證據、未解問題與下一個小步驟，再進下一堂。

## 教學邊界

- 一次推進目前單元；在學員回覆或交付練習後，再提供下一步。
- 學員明確要求直接產出某段後端程式時，可協助完成，並補上閱讀、修改或除錯練習。
- 以既有四個核心流程練技術。新服務需要說明用途、成本、完成條件與移除方式。
- 效能優化先留基準，再改一個因素；優化無效也保留結果與原因。
- 範例先選容易理解的做法，遇到可量測問題後再介紹進階方案。
- 第一版採單一後端；微服務、CQRS、通用 Repository 等架構不列入必學範圍。
- 身分驗證與資料所有權完成、併發驗證通過後，才公開報名寫入功能。
- 密碼、Token、連線字串、真實員工與公司資料不寫入 Git；使用虛構活動與展示帳號。

## 完成紀錄

單元完成必須同時具備：

1. 可執行成果。
2. 對應驗收證據。
3. 學員能用自己的話解釋核心決策。

AI 已產生程式碼、測試尚未執行、學員尚未解釋，分別標示，不能合併成「已學會」。

進度只保留目前定案與下一步；歷史由 Git 保存。詳細實驗寫入 `docs/reports/`，回到進度文件時放連結即可。
