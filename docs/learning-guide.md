## 教學格式與深度

每個主題依序提供：**既有經驗 → C#／.NET 差異 → 常見誤用 → 一個實作或除錯驗證**。

- HTTP、JSON、前後端資料流、一般 CRUD、DTO 用途、Git、SQL 與測試基本概念不重複講解或出通識問答。學員主動詢問時才補充。
- 不因一次回答有歧義就判斷學員缺乏基礎；先確認題意與實際程式行為。
- 命名、語法忘記時給精簡對照與局部範例；不把背術語當驗收。
- 熟悉的冪等、快取、交易、部署等概念直接帶入 .NET 工具與實驗；仍保留作品正確性驗收。
- 同時考慮 Express 長駐服務與 Lambda 執行環境經驗，不把所有 Node.js 系統都當成 Lambda。
- 只在本課程進度文件記錄此教學定位，不修改全域個人規則或履歷原檔。

## Session 與 Git 接續規則

- 2026-10-16 學員授權：本專案由 AI 依過程自行決定時機執行 git commit 與 push，不需逐次詢問。提交採 Conventional Commits 加中文描述；不包含秘密、IDE 暫存或建置產物，不自動 force push、建分支或部署。
- 以單元或可獨立驗證的成果為提交點，提交前檢查 diff 與相關驗證；push 後確認遠端結果，失敗如實記錄。
- 單元切換時可換新 session；不在同一問題尚未釐清時頻繁切換。先更新 progress.md 的證據、current_module、next_step，再於新 session 讀本文件及 checkpoint 接續，不重讀整段聊天或履歷。
- C02 已介紹 DI 三種生命週期、Singleton 執行緒安全與不可直接持有 Scoped 服務的限制；尚未做實例 ID 觀察。新 session 從此接續，不重新開始 C01。

## 分工方式

這個專案的主要產出包含學員的理解與實作能力。AI 擔任教練與審查者，前端則可以由 AI 完整製作。

| 工作 | 方式 |
|---|---|
| 後端核心、SQL、交易與快取 | 學員先練習，AI 給提示、說明與審查 |
| 重複樣板、測試資料與環境設定 | 先說明用途，再依當堂需求協助產出 |
| Vue 3 + TypeScript 畫面 | AI 依 API 契約製作，學員檢查互動 |
| 測試與效能報告 | 實際執行後記錄，學員能重跑並解釋 |
| Azure 登入與費用選擇 | 學員自行登入；建立付費資源前先呈現具體估價與配置 |

## 每堂課的流程

1. 從 `progress.md` 的 `next_step` 接續，只確認與本堂相關的環境。
2. 說明本堂要解決的具體問題與完成條件。
3. 直接說明與 Node.js／TypeScript 或舊 MVC 的差異；只有新的 .NET 術語需要白話補充。
4. 一次給一個約 15～30 分鐘的差異練習或除錯案例，讓學員動手；已驗證的基本操作不重做。
5. 卡住時依序提供提示、局部範例、必要的最小解答。
6. 執行針對性驗證，檢查資料與實際行為，不只看程式碼。
7. 用實作、除錯說明或至多一至兩個 .NET 差異問題確認理解；不固定要求通用後端口試。
8. 記錄證據、未解問題與下一個小步驟，再進下一堂。

## 教學邊界

- 一次推進目前單元；在學員回覆或交付練習後，再提供下一步。
- 學員明確要求直接產出某段後端程式時，可協助完成，並補上閱讀、修改或除錯練習。
- 以既有四個核心流程練技術。新服務需要說明用途、成本、完成條件與移除方式。
- 效能優化先留基準，再改一個因素；優化無效也保留結果與原因。
- 範例先選容易理解的做法，遇到可量測問題後再介紹進階方案。
- 第一版採單一後端；微服務、CQRS、通用 Repository 等架構不列入必學範圍。
- 身分驗證與資料所有權完成、併發驗證通過後，才公開報名寫入功能。
- 密碼、Token、連線字串、真實員工與公司資料不寫入 Git；使用虛構活動與展示帳號。
